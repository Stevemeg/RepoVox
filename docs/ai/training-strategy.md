# Director training and release strategy

Proposed pathway, 2026-10-08. No dataset collected, weights downloaded, training run or adapter produced. [Evaluation](evaluation-plan.md) · [Licenses](model-selection.md) · [Security](../security/threat-model.md) · [Research costs](../operations/cost-model.md#research-and-specialization-budget)

## Stage A: Baseline

Freeze upstream model revision/license/tokenizer, prompt, schema, quantization and engine. Evaluate unchanged base under the complete rubric before data collection or fine-tuning commitments. Record outcome as `base_only`; adapter/checkpoint/dataset metadata null. PASS means technical-trust/safety criteria and feasible measured latency/memory at approved cost, not superiority to a paid API. FAIL triggers prompt/context/alternative-base review; no paid fallback. Only owner-authorized, independently validated phase advances to dataset work.

## Stage B: Dataset development

Begin with 50–100 reviewed repository families, target 1,000 high-quality examples only after annotation feasibility established; expansion to 5,000 requires budget/quality review. Examples pair verified PKM/evidence/verdicts with explanations, safe graphs, storyboards and narration, including negative/uncertainty cases. No automatic harvesting of customer repositories, prompts or videos. Public GitHub availability is not unrestricted training permission.

Manifest per example: stable example/family ID, canonical repo URL, full commit SHA, source file/range/hash, SPDX/actual license text digest, copyright/notices, training-use permission basis and scope (explicit permission or reviewed license), attribution obligations, source/capture date, allowed redistribution/retention, author-created label provenance, synthetic generator/version/terms if any, reviewer/rubric/status, secret/privacy checks, dedup fingerprint, split, dataset version and deletion tombstone. Do not fabricate real reviewers; Stevemeg annotates, ChatGPT independently audits technical evidence and an owner-approved independent human reviewer is required at comparative evaluation (no reviewer currently appointed); external contributions retain legitimate attribution if ever approved.

Use explicitly permitted/owner-authored synthetic repositories and reviewed permissive sources first. No-license, ambiguous/proprietary, credential-containing, personal/private/customer code, nonconsensual voice/personal records, license-incompatible/copy-restricted data prohibited until separate documented rights decision. Copyleft/attribution-heavy sources require explicit compatibility review rather than blanket assumption. Model-generated targets are labelled synthetic and human verified against source; external generation needs owner authorization and training-use terms. Base license is separate from source-data/label/adapters rights; claims about complete upstream pretraining provenance cannot be invented.

Ground truth: static analyzer verifies ranges/symbols, reviewed fact assertions must be entailed; graph edges have support and uncertainty, README conflicts explicitly labelled. Two-pass annotation by maintainer, independent audit at least 10%/100 examples (whichever larger when available), adjudicate disagreements before promotion. Reject examples teaching executable scene code, inflated verification or unqualified dynamic behavior.

Dedup exact content hashes plus normalized AST/text fingerprints and near-duplicate similarity. Split **by repository family** (forks/templates/generated variants/transitive clones grouped), proposed 80% train/10% validation/10% test. Freeze held-out eval families before dataset construction; no descendants, revisions, copied snippets, quantization calibration or synthetic paraphrases from test in training. Detect benchmark contamination by known public benchmark hashes/IDs, timestamp and family audit; base pretraining contamination may be unknowable, so add owner-created hidden fixtures and disclose limitations. Validation tunes hyperparameters; test opened only for final comparative evaluation, no iterative test tuning.

Dataset version immutable manifest+checksums+license inventory+split assignments+tool revisions. Private research bucket separate from customer objects; encrypted role-scoped storage. Deletion request removes affected examples/raw copies/versions ≤24h, records suppression IDs through backup lifetime, invalidates descendant dataset versions and tracks every dependent checkpoint. Retrain from clean data or withdraw adapters when rights withdrawn; deleting a row cannot prove model unlearning. If deployed adapter cannot meet deletion obligations, revoke it and rollback until clean replacement passes. Never promise removal from upstream base training. Rights/annotation labor costs tracked separately from inference.

## Stage C: Specialization

Use supervised PEFT to teach source-constrained narration/scene structure and honest abstention, not pretrain a foundation model. [LoRA](https://arxiv.org/abs/2106.09685) and [QLoRA](https://arxiv.org/abs/2305.14314) reduce trainable footprint; memory/performance for RepoVox must be measured. Start dense 14B QLoRA/NF4 training on a separate 48–80 GB GPU (A100 80 GB conservative budget), no production host/customer data. Training quantization differs from AWQ serving quantization.

Investigate ranks 8/16/32, alpha 16/32/64, dropout 0–0.05, learning rate 5e-5–2e-4, 1–3 epochs, AdamW, warmup 3–10%, BF16 compute, gradient checkpointing, sequence 2k/4k, microbatch 1–2 with accumulation to effective batch 16–32. Start attention projections; expand targets only after memory/quality profiling. Loss masked to target JSON, preserve refusal/uncertainty examples; no blind optimization of verbosity. Packing must preserve example/tenant boundaries. Hyperparameters are ranges to investigate, not executed recipes.

Three proposed trials ≤32 GPU-hours each plus 16 evaluation hours; hard research cap, termination on overrun. Save adapter/optimizer/scheduler/RNG/data-cursor checkpoints hourly or ≤500 steps; checksums, training code/image/CUDA/library/tokenizer/base hashes, seed and full config captured. On preemption/OOM resume only verified checkpoint and immutable manifest; altered data/base requires new run. Check gradients/NaNs, overfit/hallucination/JSON trends and early stop. Retain last-known-good training checkpoint, not overwrite final candidates. Adapter load compatibility validated against exact base revision; merging or re-quantizing produces distinct release/hash and requires full re-evaluation.

## Stage D: Evaluation

Compare candidate and unchanged base on identical frozen held-out families/prompts/schema/hardware, with the candidate training split inaccessible. Both must meet [hard gates](evaluation-plan.md#acceptance-thresholds), retain N-01 and security/scene renderability. Promotion also requires one measured benefit: ≥2 percentage points evidence-entailment accuracy (paired confidence analysis), ≥20% fewer first-pass schema/consistency failures, or ≥15% lower p95 latency/GPU-seconds under matched quality. No claim-accuracy regression >1 point, no language slice >2 points, zero new severe hallucination/safety/license/privacy failures. If base at ceiling, latency/consistency benefit may qualify; cannot reduce context/workload unfairly.

FAIL: no production promotion, archive report/checkpoint privately, investigate data/recipe or keep base-only identity. Specialization is a product goal, not a claim achieved by naming an endpoint. If no qualified adapter exists, escalate whether to delay launch or approve explicitly labelled base-only service; owner approval and revised roadmap required, never quietly claim custom training.

## Stage E: Release

Package immutable base+adapter or derived merged quantized artifact, tokenizer, prompt/schema/render compatibility, engine/image digest, complete SHA-256 manifest, dataset version/rights inventory, training run config, evaluation report and license/NOTICE bundle. Owner signs release manifest; registry read-only to serving, no public upload/default hub publishing. Base-only release records null adapter/dataset; specialized release names actual adapter/run and upstream origin, never “trained from scratch”.

Promotion gates: reviewed rights/security; baseline/candidate comparative PASS; artifact and runtime compatibility; memory/load/cold-start/replay tests; staging whole-video and tenancy checks; owner release approval and independent validator PASS. Pin production release alias atomically, route new jobs only; in-flight jobs keep old release. Rollback selects prior verified manifest; revoke compromised/rights-invalid release, invalidate dependent caches, retain audit metadata. A rollback cannot change a running job's model silently; fail/retry new job explicitly if required. Training account has no production DB/customer prefix/inference credentials; serving has no dataset/checkpoint write role.
