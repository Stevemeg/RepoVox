# Security threat model

Proposed, 2026-10-08. Treat public repositories, model responses and client IDs as untrusted. **Never execute submitted repository code.** [Pipeline](../architecture/pipeline.md) · [Ownership](../architecture/data-model.md#entities-and-ownership) · [Operations](../operations/deployment.md)

## Assets, actors and trust boundaries

Protect account sessions, tenant projects/history, source snippets, internal inference credentials, model weights, licensed datasets, artifact objects, usage reservations, integrity of claims and availability/cost. Adversaries include malicious submitters/repo maintainers, compromised model output/dependencies, stolen sessions and accidental secret exposure. Public source is not consent for unrestricted retention, external disclosure or training.

Boundaries: browser→BFF/API; API→managed identity; API/worker→owner-scoped PostgreSQL; queue→worker (IDs not authority); acquisition→archive extraction/parser; parser→sanitized AI payload; AI output→validated trusted scene data; renderer→private objects; API signing→browser delivery. Infrastructure/migration/operator roles are outside ordinary user authority and require audit. [Architecture diagram](../architecture/overview.md#architecture-diagram) shows these paths.

## Controls and accountable implementation locations

All controls below are launch requirements, not implemented protections. Owner maintains them; independent validator reviews gate results.

| ID / Threat | Enforceable mitigation and boundary | Residual risk / evidence to collect |
| --- | --- | --- |
| S-01 Malicious files/parser exploits | Acquisition streaming caps from PRD; safe extraction rejects traversal, absolute/drive/UNC paths, NUL, Unicode-normalized/case collisions, duplicate members, symlinks/hardlinks/devices/FIFOs/sparse entries, nested archives. Resolve each destination under fresh scratch root; no link following, exclusive file creation. Parser task non-root/read-only image, bounded writable scratch, CPU/memory/task timeout. Only pinned safe parsers; no deserialization/pickle/eval. | Parser CVEs possible; fixture suite and patched images, task role restricted to assigned job objects. |
| S-02 Git hooks/submodules/code execution | Acquire GitHub archive at SHA, not checkout. Ignore `.git`, hooks, `.gitmodules` entries, Git config, LFS pointer payloads; never git submodule/LFS fetch. No pip/npm installs, test runner, module import, shell command from repo, compiler plugins or project browser content. YAML safe loader/custom tags rejected. | Static analysis misses runtime behavior; enforce process/egress audit and known execution tripwires. |
| S-03 Resource exhaustion | Streaming limits, extracted totals/file count/size, parser timeouts, JSON/YAML depth ≤32, string length bounded per schema; source/token/TTS/video/job caps. One job/task, ≤10k frames at video maximum (9000 frames expected), scratch ceilings, memory termination, admission limits and cost reservations. | CPU-expensive parser inputs require per-file watchdog; rejects reported separately from supported successes. |
| S-04 SSRF/input URL | Parse strict canonical GitHub URL, no redirects from user URL. Construct API/archive paths internally; allow only `api.github.com` and `codeload.github.com`, HTTPS/443, validate redirects if any against same explicit allowlist (max 2). Resolve DNS at connection, reject non-global IPv4/IPv6 incl metadata/loopback/link-local/private; proxy revalidates each redirect and pins accepted address/TLS hostname to avoid rebinding. | GitHub outages/rate limits; no arbitrary provider URL overrides from request/content. |
| S-05 SSRF/remote assets | No repository image/media/fonts/README URLs fetched. Approved static template assets bundled in image. Render task no internet route; SG permits only required DB/Redis/S3 endpoints. Chromium request interception denies everything except loopback trusted asset server; metadata endpoints denied in browser interceptor, environment scrubbed. FFmpeg protocol allowlist local files/pipes, argument arrays, no shell. | Browser/parser escape remains possible; no broad role or secrets in render task. Validate Chromium sandbox on target platform; no `--no-sandbox` convenience exception. |
| S-06 Prompt injection | Fixed system prompts, source quoted as untrusted data, no tools/browsing/function execution, narrow structured output schemas, claim/evidence allowlists, output length caps. Repo text cannot set model/owner/prompt/budget or verification status. Never evaluate generated commands/JSX/SQL. Post-narration claim checks. | Models may still misinterpret data; deterministic evidence gates plus human fixtures, fail closed when support absent. |
| S-07 Accidental secrets | Before local inference/TTS/artifact rendering, scan filenames/content/high-entropy tokens/key patterns; exclude `.env`, credential/config/key material and known private keys. Redact suspicious spans with stable placeholders while preserving line numbers; do not emit secret-derived claims. High-confidence secret detection halts `secret_detected` by default before GPU work and cleans scratch. No raw code/provider response in logs/telemetry. | Scanners miss secrets; transmit minimal snippets, minimal private inference access and deletion controls. User override not offered in V1. |
| S-08 Source leakage/privacy | Self-hosted private gateway/engine with no runtime internet, prompt/response logging or training reuse. Redacted selected evidence only to Director, narration only to TTS. Private encrypted storage/TLS, service grants and least privilege; processing notice names actual compute locations. External AI experiment requires explicit owner approval, permitted data/license/privacy basis, terms/retention/DPA/residency record and separate credentials/budget; disabled for normal generation. | Hosting operator access and undetected secrets remain risks; customer processing consent does not grant training rights. Any external terms unresolved blocks that experiment, never causes silent fallback. |
| S-09 Tenant isolation/IDOR | Validate issuer/audience/client ID/token_use/expiry/algorithm/JWKS; derive owner from subject. Owner-scoped SQL + RLS + composite owner FKs, URL/body owner ignored. Leased-worker procedures verify owner/fence; stage messages cannot override ownership. No shared cross-tenant caches. | Privileged admin paths tightly scoped/audited, no API BYPASSRLS. Negative tests for every persistent entity. |
| S-10 Objects/signed URLs | S3 block public access, encryption at rest/TLS, least-privilege prefix/endpoint policies. API checks owner/tombstone before minting ≤5-minute signed media grant; stream route validates grant/revocation on each request, reserves bytes atomically, caps ranges/concurrent streams and rechecks revocation at ≤5s chunk boundaries. No direct S3 URLs; no signed links in logs/history, `no-referrer`. Client cannot set bucket/key. | Bearer grants can be shared until revocation but cannot bypass byte quota; already received bytes cannot be revoked. All S3 versions purged on deletion. |
| S-11 Auth/session/XSS/CSRF | Cognito authorization code+PKCE, OIDC state/nonce, exact callbacks. BFF rotated opaque server session, HttpOnly/Secure/SameSite=Lax cookie, no localStorage tokens; CSRF/origin validation, fixed CORS, source/text escaping, CSP and HTTPS/HSTS. Access TTL ≤15 min, idle session 24h/max 7d; logout invalidates session/refresh and delivery grants; JWKS bounded cache/rotation. | Already received media cannot be revoked; refresh/session/grant revocation tests needed. |
| S-12 Supply chain | Lock exact deps/grammar/container digests, trusted registries, SBOM/license audit incl Remotion/FFmpeg, vulnerability scans on CI and weekly, no repository deps installed. GitHub Actions pinned by commit SHA in implementation, minimal permissions/OIDC, no secrets for fork PRs, deployment gated. No automated bot commits. | Critical reachable vulnerability blocks release; exceptions require owner risk record and expiry, never blanket ignore. |
| S-13 Abuse/cost | Per-user/IP admission limits, one active/ten queued per owner, finite pilot allowlist and operator quotas, global concurrency, atomic budget reservations, request/file/token/character ceilings, warm GPU/autoscale budget caps and admission/inference kill switches. Auth required, no unlimited free tier. Do not replay active unknown engine requests or exceptional unknown paid outcomes. | Infrastructure accounting may lag; reserve pessimistically and fail closed when ledger unavailable. IP limits need shared-network tuning. |
| S-14 Data/operator exposure | Retention/tombstone cleanup and restore suppression ledger, private backups, role separation, access audit, trace redaction. Operator break-glass access time-bound with reason; never log customer content. | Public repo might become private/deleted; revoke new acquisition, inform owner existing video policy. Licensing/takedown process reviewed before launch. |
| S-15 Model/registry compromise | Approved publisher verifies upstream revision/full hashes/license, signed release manifest, safe tensors, trusted tokenizer/config and pinned container/CUDA dependencies. Disable remote code/untrusted pickle in serving; TTS conversion isolated build lane after inspection. Registry write role separate, runtime read-only current/prior approved prefixes. | Signed malicious upstream still possible; provenance review, synthetic startup tests, vulnerability scans and revocation/rollback required. |
| S-16 Dataset poisoning/malicious examples | Training lane isolated; rights-reviewed manifest, reviewer-verified evidence labels, synthetic flag, duplicate/family splitting and benchmark quarantine. Reject examples that reward unsupported claims, leaked secrets, executable scene code or instruction override. Independent holdout and adversarial evaluation before promotion. | Subtle poisoning requires sampled manual review and comparison with unchanged base; not solved by schema validation. |
| S-17 Memorization/leakage | Never train on customer prompts/repositories by default. Licensed curated records only, secrets/privacy filtering; canary extraction and nearest-neighbor leakage tests on candidate adapter, document residual leakage risk. No global prompt logs or generation corpus collection. | PEFT can memorize; zero known sensitive canary leakage gate, withdraw/retrain if detected, no claim of perfect forgetting. |
| S-18 Cross-tenant inference/cache | Owner-bound operation/fence/release grants, request isolation, no cross-request KV/prefix cache baseline, owner-scoped artifact/context keys. Engine output must match requesting job IDs; clear transient buffers and prohibit debug dumps/core dumps with content. | GPU host is privileged; never share customer service with research/community workloads. Two-owner canaries/restarts/drain tests. |
| S-19 Unauthorized inference/GPU DoS | No public engine/admin port; private SG/tunnel + TLS authenticated gateway, <=60s stage grants checked against DB, schema/token/KV limits, one active sequence/GPU and one/owner, eight pending requests. Reject arbitrary weights/adapters/logits/tools/stream flood. Budget/timeout/abort and forecast kill switch. | Inventory shortages and OOM can delay jobs; enforce rate/concurrency before allocation, no paid API escape. |
| S-20 Model/data license compliance | Registry release stores authoritative base/software/voice licenses and notices separately from independent dataset/adapter grants. Dataset record requires actual training-use basis, attribution/deletion obligations and reviewer sign-off. Missing/ambiguous permission or voice rights blocks training/release. | Apache base license does not license repository training data or voice persona. Obtain owner legal/rights decisions before downloads/training/deployment. |
| S-21 Training deletion/provenance | Versioned repository family/commit/source-license/permission/transform manifests, dependency graph dataset->run->adapter->release. Tombstone withdrawn data <=24h, invalidate dependent adapters immediately, purge live copies and suppress backup restore; retrain cleanly and evaluate before re-promotion. Minimal content-free hashes retained for accountability. | Removing examples does not remove learned influence; do not claim unlearning by file deletion. |
| S-22 Accidental publication | Private dataset/weights/checkpoint/operation buckets, registry deny public ACL/policy, no publishing CI or model hub push. Separate research/prod IAM, secret scan export bundles, inspect release package for prompts/source/private keys before distribution. | Bucket/config mistakes need anonymous-denial and deployment-diff tests. Upstream open weights do not imply RepoVox customer prompts may be public. |

Task profiles in [deployment](../operations/deployment.md#worker-profiles-and-resource-limits) are part of these controls. Container isolation cannot be asserted secure without adversarial tests; Chromium sandbox/egress validation is a launch blocker. Source parsers receive no inference credentials; renderers receive no raw archive; model output is data only.

## Security acceptance suite

These are required future tests; none have run in Phase 0.

| Suite | Testable acceptance |
| --- | --- |
| SEC-A (S-01/02/03) | Crafted traversal/link/device/collision/tar-bomb/large-file fixtures rejected within configured limits, no writes outside scratch. Repo containing hook/npm script/Python import side effects creates no tripwire files/processes/network calls; submodule/LFS URLs never requested. Parser hang killed within cap, quota not exceeded. |
| SEC-B (S-04/05) | URL credentials/IP/port/query/malformed hosts rejected. DNS rebinding/redirects to RFC1918, IPv6 loopback/link-local and `169.254.169.254` blocked at connection; repo/model remote asset attempts produce zero outbound requests. Chromium network interception/sandbox tested in actual chosen worker image. |
| SEC-C (S-06/07/08) | Repo instructions to ignore policy/exfiltrate/invent paths/emit JSX cannot change config/claims or execute. Canary secrets never appear in inference payloads, sidecar, video, logs/traces; secret policy rejects high-confidence canary before inference call. Local processing notice documented; any approved external experiment terms separately recorded. |
| SEC-D (S-09/10) | Two-owner tests cover users/sessions/projects/snapshots/jobs/stages/attempts/artifacts/storyboards/videos/grants/usage/operations/outbox/deletions, guessed IDs, cross-owner FKs, caches and replayed stage messages. No access/URL leakage; missing RLS owner fails closed; private bucket denies anonymous GET; expired/revoked grants and concurrent byte-quota replay rejected. |
| SEC-E (S-11) | Wrong issuer/client/audience/algorithm/token_use/expired tokens rejected. CSRF/callback replay/XSS source fixtures blocked; logout revokes server session and refresh; callback state/nonce single-use. Browser cannot read session cookie/access token. |
| SEC-F (S-12/13/14) | Concurrency race cannot over-reserve quota/budget. DB unavailable means zero new inference sends. Duplicate deliveries no simultaneous duplicated engine operations or duplicate settlements. Critical vulnerability scan blocks release; fork CI has no deployment credentials. Deletion purges all live versions ≤24h and restore does not revive deleted users/artifacts. |
| SEC-G (S-15/16/20/21/22) | Corrupt/unsigned/mismatched weight/tokenizer/adapter or missing license manifests fail startup/promotion. No unsafe deserialization/remote model code; contaminated family/benchmark and poisoned unsupported/command-output examples are quarantined. Rights withdrawal invalidates dependent releases and removes live source <=24h; restored backups stay suppressed. Anonymous registry/dataset reads and ordinary tenant writes return denial. |
| SEC-H (S-17/18/19) | Two-tenant canary prompts never appear in other's outputs/cache/logs/restarts. Unauthenticated/public/expired/wrong-fence gateway requests rejected before GPU allocation. Over-context, >8 pending, owner concurrency and GPU budget abuse cannot over-allocate. Abort/reset reconciles all affected operations; zero known sensitive canary extraction in model release evaluation. >=100 adversarial prompt/output fixtures yield zero executed code, outbound requests or falsely verified policy overrides. |

Outstanding risks: static inference quality, parser/Chromium/CUDA vulnerabilities, undetected secrets, upstream model/data/voice rights, subtle poisoning/memorization, GPU availability, privileged hosting access and bearer-link sharing. Controls require later evidence and cannot establish production security from Phase 0 docs. [Evaluation](../ai/evaluation-plan.md) and [training](../ai/training-strategy.md) provide model-specific gates.
