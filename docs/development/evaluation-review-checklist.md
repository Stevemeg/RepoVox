# Annotation and review checklist

Version `review-checklist-1.0`, 2026-10-12. [Handbook](evaluation-authoring.md) · [Human appointment](evaluation-reviewer-packet.md) · [Freeze batches](evaluation-batches.md).

For each family, retain an authenticated private preparer checklist and independent
reviewer's per-row decisions. No checked boxes are prefilled here.

- Rights, scoped source, full SHA, notices, retention and reviewer access approved.
- Original file checksums and exact inclusive LF ranges valid; repository/SHA matches
  source manifest; no cross-repository citations or fabricated locations.
- Symbols, functions/classes, parameters, imports and aliases faithfully described.
- Entrypoint candidates, multiple candidates and unimplemented declaration targets
  qualified; no runtime execution asserted.
- Every edge has real source/target/support and manual relationship review; inferred,
  unresolved and declared relationships retain their qualifications.
- Every technical assertion has an independently authored ID, exact atom and expected
  status; no duplicate facts or approval conflicts. Missing/invented functions use
  actual negative evidence and expected abstention, never nonexistent citations.
- README/comment/source conflicts and insufficient evidence recorded in the reviewed
  rubric/expectations; broad semantic assertions not relabeled as syntax facts.
- Preparer and appointed reviewer distinct actual people; conflicts disclosed; no
  analyzer/model agreement used as independent human evidence.
- Complete claim/edge row coverage, variants and all disagreements adjudicated; no
  unresolved rows and no partial gold accepted.
- Receipt digest covers final source/labels/split/rights/variant membership; both
  parties' private evidence retained; later changes trigger a new version/re-review.
- Family ancestry, fingerprints, cross-split checks, hidden authorship and access
  obligations reviewed. Final evaluation only access cannot become prompt tuning.
- Scorer/schema/source checks recorded separately from semantic/human approval.

Freeze checklist additionally requires actual storage/identity/mount/access review,
backups/withdrawal lineage, owner budget and retention authorization, immutable manifest
hashes and all approved counts. A tooling test's synthetic receipt checks software,
not any of these official approvals.
