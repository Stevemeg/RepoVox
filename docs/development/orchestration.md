# Phase 1 durable job orchestration

[Authoritative state/timeout contract](../architecture/data-model.md) · [Reliability](../operations/reliability.md) · [Testing](testing.md)

Job state is PostgreSQL truth. Celery/Redis deliver stage/deletion IDs only and retain no authoritative results. The dispatcher polls every five seconds, commits publication acknowledgement only after send and leaves failed sends in the outbox. Reconciliation recovers published-but-unclaimed ready stages after 30 seconds, expires leases, makes due retries ready, enforces the 45-minute absolute deadline and republishes pending cleanup notifications. Duplicate delivery is expected.

Admission atomically creates the owner-scoped server fixture snapshot, queued job, all fourteen stage rows, first ready-stage outbox event, quota reservation and ledger entry. A global advisory lock plus per-owner quota lock serializes monthly and owner quotas. Production generation remains unavailable. Fixture quota defaults follow the approved pilot ten/user/month, 100 total/month, ten queued and one active/user, two new admissions/minute/user. Monthly reservations remain counted after settlement; retry creates a new reservation. Owner/key uniqueness returns the existing job for an identical canonical request digest and 409 for changed project/fixture/prior/version. A zero-measurement fixture budget unit is an accounting scaffold; GPU/token/TTS/CPU/render/storage/delivery measurements can be recorded through ledger JSON but no paid prices/charges are invented.

The preserved stage keys are `validate`, `acquire`, `filter`, `structure`, `entrypoints`, `infer`, `knowledge`, `evidence`, `verify`, `storyboard`, `narration`, `tts`, `render`, `encode`. Validate is marked succeeded only for trusted fixture admission, not real repository validation. Acquire writes a harmless synthetic JSON object; filter deliberately terminates at `failed` with `phase1_fixture_boundary`, and remaining stages become failed. The UI explains this is an infrastructure demonstration, not a generation failure for an acquired customer repository and not a completed video. No real stage handler exists in Phase 1.

Claims lock owner quota then job/stage in consistent order, require eligible ready state and a live reservation, and enforce one active job/user. Claim increments the monotonically increasing fence and appends a unique attempt. Lease lasts up to 60 seconds; heartbeat extends it only under the current fence, job state, stage deadline and project authorization. Stage timeout/max-attempt values are copied from Phase 0 (acquire three attempts; other later stages two; validate one). Short fixture handlers complete within one heartbeat interval; the reusable heartbeat boundary supports future long loops. No GPU work exists to abort/reconcile here.

Every finish/fail/heartbeat validates the database fence and clock. An expired/replaced/cancelled worker cannot commit an output pointer. Output write uses a new UUID and checksum, a tenant/snapshot/job prefix and conditional create; read verifies body checksum before database publication. Unique stage output prevents duplicate commits. A rejected stale publication deletes its uploaded fixture object; project cleanup deletes all objects under DB-resolved snapshot/job prefixes, including abandoned pre-publication objects. Crash-created orphan objects for a still-live project are a known retention limitation until the later retention sweeper.

Transient fixture failure persists backoff `min(120,5*2^(attempt-1))` seconds plus 0–5 seconds jitter; lease-loss recovery uses the same base delay. Attempt/deadline checks prevent unbounded retry. `transient_once` provides a deterministic first-attempt error, `permanent_failure` a terminal error. SQL triggers reject unlisted transitions and changes to terminal job/stage rows. Retry is a new job, never a terminal reset. Cancellation serializes against completion, revokes fences immediately, stops future claims, records intent/epoch and settles the harmless fixture reservation. Future inference cancellation still requires confirmed engine stop/unknown-usage reconciliation under Phase 0.

Deletion first tombstones project visibility and cancels active jobs, then commits a deletion request/cleanup notification. All project/job HTTP endpoints revoke access immediately. Cleanup is idempotent and tracked durably. Minimal tombstoned DB metadata and history currently remain; complete 24-hour live-data purge, account/identity deletion, versioned object removal, backup suppression, expired-data sweeps and production restore guarantees are later phases. Do not interpret a local cleanup-completed record as proving those guarantees.

Fixtures test leases, worker replacement, duplicate output, real Redis publication/loss and actual S3 reads/deletion. The [verification record](../delivery/phase1-verification.md) separates executed results from requirements not yet exercised. These local checks establish no SLA, GPU/video throughput or full production security.
